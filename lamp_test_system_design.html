XS-XLD5 V3.0 大路灯控制板 — 产测上位机系统设计方案

PRODUCTION TEST SYSTEM · PYTHON + PySide6 · 测试数据全流程记录 · 固件 v5.0 / OTA 已打通

1. 系统概述

针对 XS-XLD5 V3.0 大路灯控制板（ESP32-C3, ESP-IDF v5.4.4 + FreeRTOS, FastBee MQTT，当前固件 v5.0）设计产线测试上位机系统。系统通过 UART 串口产测协议与 DUT 交互，自动执行按键/调光/模式/记忆/MQTT/OTA 等测试项，将测试结果完整记录到 SQLite 数据库，并提供良率统计与不良品分析。

设备端 OTA 双分区升级已实测打通（v4.0 → v5.0，ota_1 → ota_0 双向切换均验证通过），因此产测需覆盖「运行分区 + 固件版本」校验，见 第 10 节。

SN 扫码
→
加载测试序列
→
UART 下发指令
→
DUT 响应采集
→
PASS / FAIL 判定
→
SQLite 入库
关键前提：固件需新增「产测模式」。产测模式下：缓起/缓灭时间缩短（1.5s → 200ms）、夜灯 30min 超时参数可配置、开放按键模拟指令与状态查询指令。单台测试目标 < 30 秒。

4. 产测通信协议（固件需实现）

串口 115200-8-N-1，行协议，应答格式 +CMD:value OK 或 +CMD:value ERR：

指令方向说明应答示例
AT+VER?Q查询固件版本+VER:XS-XLD5-1.0.0
AT+ENTER_TESTC进入产测模式（缩短渐变、可配置夜灯超时）+TEST:1
AT+KEY=<id>,<evt>C模拟按键：id=0开关 1上 2下 3阅读 4夜灯；evt=SHORT/LONG/DBL+KEY:OK
AT+STATE?Q查询系统状态+STATE:NORMAL
AT+PWM?Q查询上下灯 PWM 占空比+PWM:100,5
AT+BRIGHT=<u>,<l>C直接设置亮度（0-100）+BRIGHT:OK
AT+NVS_WRITEC写记忆，配合断电验证恢复+NVS:OK
AT+NVS_ERASEC清除记忆+NVS:OK
AT+WIFI?Q查询 Wi-Fi 状态与 RSSI+WIFI:1,-52
AT+MQTT?Q查询 MQTT 连接状态+MQTT:1
AT+NIGHT_TIMEOUT=<sec>C产测模式配置夜灯超时（默认 30min）+NT:OK
AT+OTAINFO?Q查询当前运行分区 + 固件版本（OTA 校验用）+OTAINFO:ota_0,5.0
AT+PART?Q查询 OTA 分区状态（boot/running/next + otadata seq）+PART:ota_0,ota_0,ota_1,3
AT+OTA=<url>,<ver>C触发 OTA 升级（产线预置固件用，需先校时）+OTA:OK
AT+SNTP?Q查询时间同步状态（HTTPS 证书校验前提）+SNTP:1,1758350000
AT+OTAINFO? 的实现要点：版本读 esp_app_get_description()->version（即 PROJECT_VER），分区读 esp_ota_get_running_partition()->label。不要在固件里再写一份版本宏，两处会漂移。

5. 数据库设计（SQLite）

test_records        -- 测试主记录
  id INTEGER PK, sn TEXT UNIQUE, model TEXT, batch_no TEXT,
  operator TEXT, station TEXT, start_time TEXT, end_time TEXT,
  fw_version TEXT,                 -- 固件版本 (AT+OTAINFO?), 追溯用

  id INTEGER PK, record_id INTEGER FK, item_name TEXT,

defect_records      -- 不良品档案
  id INTEGER PK, sn TEXT, defect_code TEXT, defect_desc TEXT,
  found_station TEXT, found_time TEXT,
  repair_status TEXT(OPEN/FIXED/SCRAP), repaired_by TEXT, repaired_time TEXT

operators           -- 操作员
  id INTEGER PK, name TEXT, role TEXT(admin/operator),
  password_hash TEXT, created_at TEXT

6. 测试项清单（XS-XLD5 专用）

#测试项产测指令/方法判定标准
1固件版本AT+VER? / AT+OTAINFO?与期望版本一致（当前 5.0）
2上电指示观察 5 LED 亮 1s全部点亮后熄灭
3开关机AT+KEY=0,SHORT+STATE:POWER_ON
4上灯开关AT+KEY=1,SHORT上灯 PWM > 0
5下灯开关AT+KEY=2,SHORT下灯 PWM > 0
6长按调光AT+KEY=1,LONG,1000亮度单调变化且保存
7双击极值AT+KEY=1,DBL5% ↔ 100% 切换
8阅读模式AT+KEY=3,SHORT上下灯均 100%
9夜灯模式AT+KEY=4,SHORT上灯 5% / 下灯 0
10模式互斥阅读中按上灯键退出阅读回 NORMAL
11记忆功能设亮度 → 断电 → 上电 → 开灯亮度恢复（治具断电）
12PWM 准确性AT+BRIGHT=50,30 后读回±1% 容差
13缓起缓灭产测模式缩短版计时时间 ±30%
14MQTT 上报平台接收 property/post亮度数值匹配
15MQTT 指令平台下发 function/get设备响应并回 function/post
16Wi-Fi RSSIAT+WIFI?RSSI > 阈值
17夜灯超时AT+NIGHT_TIMEOUT=10 后验证10s 后全关
18老化测试连续运行 N 小时（离线工位）无异常复位、无死机
19运行分区校验AT+PART?boot == running，otadata seq 有效
20时间同步AT+SNTP?已同步且时间戳 > 2023 年
21OTA 升级平台下发 ota/get → 观察进度 → 重启status 2→3，重启后版本=目标版本
22OTA 回滚验证升级后不 mark valid 强制断电两次自动回退旧分区且能正常启动
OTA 测试项（21/22）耗时较长，建议放在抽检工位而非每台必测；全检工位只做 19/20（分区 + 校时，秒级完成）。测试项 21 的判定必须「重启后读版本」，只看 status=3 不够——本次实测踩过的坑就是 finish 返回 OK 但没切分区。

10. OTA 与版本管理（产测侧要点）

设备端 OTA 已打通（v4.0 → v5.0 实测，ota_1 → ota_0 双向切换均通过）。产测系统需要配合做版本与分区校验，以下是必须知道的约束：

要点说明对产测的影响
版本号单一来源 固件版本由顶层 CMakeLists.txt 的 PROJECT_VER 决定，运行时从镜像 esp_app_desc 读出 上位机不要硬编码期望版本到代码，放配置文件；换版本只改配置
平台固件版本必须一致 FastBee 上传固件时填的版本 ≠ PROJECT_VER 会导致平台无限重复下发升级指令 发布固件时双人核对；产测若发现反复重启需先查此项
分区必须 64KB 对齐 otadata 结束在 0x12000，ota_0 只能从 0x20000 起，否则编译报错 AT+PART? 返回的分区地址应固定为 ota_0=0x20000 / ota_1=0x160000
HTTPS 依赖时间同步 未校时则 mbedTLS 证书校验失败，下载必失败 OTA 测试项前必须过 AT+SNTP?（测试项 20）
升级成功判定看重启后版本 存在 finish 返回 OK 但 otadata 未写入的情况（已修复并加了手动 set_boot 兜底） 测试项 21 不能只看 status=3，必须重启后再读版本
回滚机制 新分区首启为 PENDING_VERIFY，再次重启才回滚；首启成功后 mark valid 测试项 22 通过连续两次断电验证回滚有效性
完整 OTA 流程（服务端操作 + 设备端 14 步 + 踩坑记录 + 实测日志时间线）见项目内文档： docs/OTA升级完整案例.md；端到端数据流见 esp32c3_dataflow.html 底部「OTA 双分区升级数据流」。
